## 3. Flow เป้าหมาย

เส้นทางหลักต้องเป็นเส้นตรงที่มองเห็นตลอด:

`1 เลือกชุดงาน → 2 อัปโหลด PDF → 3 ตรวจรายการ → 4 พิมพ์`

- แสดง **แถบขั้นตอน (stepper) 4 ขั้น** ใต้หัวหน้าจอ ขั้นปัจจุบันเด่น ขั้นที่ยังไม่พร้อมเป็นสีจาง พร้อมเหตุผลสั้น ๆ (เช่น "ต้องอัปโหลด PDF ก่อน")
- แสดง **ปุ่มหลักปุ่มเดียวต่อหน้า** ("ขั้นต่อไป: …") ติดด้านล่างหรือมุมขวา
- เมนูรอง (จับคู่ SKU, สำรอง/ความปลอดภัย, ตรวจปัญหา) อยู่ในกลุ่ม "เครื่องมือ" แยกจากเส้นทางหลัก

## 4. Tickets

ทำตามลำดับ แต่ละ ticket = 1 commit บน branch `ux-flow-v5` และต้องรันเทสต์ผ่านก่อน

### UX-01 Navigation และคำเรียก (ขนาด S)
- รวมเมนูเหลือชุดเดียว (sidebar) ลบปุ่มซ้ำในหัวหน้าจอ (3321–3326) หรือเหลือเฉพาะ action ที่ไม่ซ้ำ
- จัดกลุ่ม: **งานหลัก** (ชุดงาน, อัปโหลด PDF, ตรวจและพิมพ์) / **เครื่องมือ** (จับคู่ SKU, ตรวจปัญหา, ความปลอดภัยข้อมูล)
- เปลี่ยน "พิมพ์" → "ตรวจและพิมพ์" ให้ตรงปลายทาง
- ลบป้าย "Frontend V3" (3314) ใส่เวอร์ชันเล็ก ๆ ไว้หน้า "ความปลอดภัยข้อมูล" แทนได้
- Acceptance: ทุกหน้าไปถึงได้ด้วยเมนูชุดเดียว, เทสต์ navigation (`packmaster-navigation-usability`, `packmaster-layout-v4`, `packmaster-collapsible-sidebar`) ผ่านหรือถูกแก้พร้อมเหตุผล

### UX-02 Stepper และปุ่มขั้นต่อไป (ขนาด M)
- เพิ่ม component `PMStepper` อ่านสถานะจาก `activeBatchId`, `orders.length`, จำนวน exception ที่เหลือ
- ปุ่ม "ขั้นต่อไป" ต่อหน้า: ชุดงาน→"อัปโหลด PDF", อัปโหลด→"ตรวจรายการ" (แสดงตลอดเมื่อมีออเดอร์ ไม่ใช่เฉพาะบางเงื่อนไข), ตรวจ→"พิมพ์" (ปิดใช้ + บอกเหตุผลถ้ามีรายการต้องตรวจ)
- ห้ามเปลี่ยนพฤติกรรม gating ของการพิมพ์ (fail-closed เดิมต้องคงอยู่)
- Acceptance: ผู้ใช้ใหม่เดินครบ 4 ขั้นโดยไม่ต้องเดา, ทดสอบด้วย `docs/PILOT_SAMPLE_DATA.json`

### UX-03 แทน `window.confirm` ด้วย dialog ในแอป (ขนาด M)
- สร้าง `PMConfirmDialog` (focus trap, Esc ปิด, โฟกัสเริ่มที่ปุ่มปลอดภัย, `role="alertdialog"`)
- ปุ่มบอกการกระทำ เช่น "นำเข้าซ้ำ" / "ข้ามไฟล์นี้", "ลบถาวร" / "ยกเลิก" ปุ่มทำลายข้อมูลเป็นสีแดง
- รวม confirm ตอนอัปโหลด (ไฟล์ซ้ำ 1516 + order ซ้ำ 1864) เป็น **dialog สรุปเดียว** ที่มีตัวเลือกต่อรายการ
- เก็บข้อความเตือนเดิมให้ครบ (ห้ามตัดคำเตือนเรื่องย้อนกลับไม่ได้ ฯลฯ)
- Acceptance: ไม่มี `window.confirm` เหลือใน `index.html` (ยกเว้นเจ้าของอนุญาต), เทสต์ที่ตรวจข้อความ confirm ถูกอัปเดต

### UX-04 ขนาดตัวอักษรและ spacing (ขนาด S)
- กำหนด type scale ใน `:root`: ขั้นต่ำ **12px** สำหรับข้อความใช้งาน (ป้ายสถานะ/badge ขั้นต่ำ 11px ต้องมี contrast ผ่าน)
- เปลี่ยน `text-[8–11px]` ทุกจุดตามรายการในหัวข้อ 2-E
- touch/click target ขั้นต่ำ 44px (ปุ่มใน sidebar มี 44px อยู่แล้ว ตรวจปุ่มอื่น)
- Acceptance: grep `text-\[(8|9|10|11)px\]` เหลือเฉพาะ badge ที่ระบุเหตุผลไว้

### UX-05 Accessibility และ motion (ขนาด S–M)
- เพิ่ม `:focus-visible` ชัดเจนทุก control (ห้ามใช้ `outline: none` ลอย ๆ)
- `aria-live="polite"` ให้แถบ progress ประมวลผล PDF (3499), ข้อความ `uploadError`, การบันทึกสำเร็จ/ล้มเหลว
- `@media (prefers-reduced-motion: reduce)` ปิด spinner/transition
- แทน `transition-all` (3299, 3499) ด้วย `transition-[width]` หรือ `transition-transform`
- dialog ทุกตัวต้องมี focus trap และคืนโฟกัสเมื่อปิด
- ตรวจ `autoFocus` ที่ 3278 ว่าไม่ขโมยโฟกัสผิดจังหวะ
- Acceptance: เดิน flow ทั้งหมดด้วยคีย์บอร์ดอย่างเดียวได้

### UX-06 คำศัพท์และข้อความ (ขนาด S) — **ต้องให้เจ้าของอนุมัติก่อนแก้**
- เสนอตารางคำศัพท์ไทยชุดเดียว ให้เจ้าของเลือก เช่น Batch → "ชุดงาน", Exception → "รายการที่ต้องแก้", Review → "ตรวจรายการ", Reprint → "พิมพ์ซ้ำ", Local Safety → "ความปลอดภัยข้อมูล"
- ข้อความ error ต้องบอกขั้นตอนถัดไป ("กรุณาตรวจไฟล์อีกครั้ง" → บอกว่าไฟล์แบบไหนรองรับ)
- ห้ามเปลี่ยนคำศัพท์ที่เทสต์/smoke ตรวจอยู่โดยไม่แก้เทสต์
- Acceptance: เจ้าของเซ็นตารางคำศัพท์ก่อน Gemini แก้ข้อความ

### UX-07 ดีไซน์ UI ใหม่ (ขนาด M–L)
ทิศทาง: **"ชนะด้วยความง่าย"** สะอาด อ่านเร็ว เหมาะหน้างาน ไม่ต้องหรู
- ใช้ Noto Sans Thai เดิม (ชุดที่โหลดอยู่แล้ว) น้ำหนักตัวอักษรไม่เกิน 800 ไม่ใช้ 900 ทั้งแอป
- สีหลัก navy เดิม (`--pm-navy: #071f3d`) สีสถานะ 4 สีใช้ชุดเดียวทั้งแอป: พร้อมพิมพ์=เขียว, ต้องตรวจ=เหลือง/แดง, รอ=เทา, พิมพ์แล้ว=น้ำเงิน และห้ามใช้สีอย่างเดียว ต้องมีข้อความ/ไอคอนกำกับ
- กำหนด design tokens ใน `:root` (สี, spacing, radius, shadow) และให้ component ใช้ token ไม่ hardcode
- การ์ดและตารางใช้ spacing สม่ำเสมอ (สเกล 4/8/12/16/24)
- **หน้า Review (ลดความแน่น):** ถ้ามีรายการต้องตรวจ ให้ default แสดงเฉพาะรายการนั้นพร้อมตัวนับ ("ต้องตรวจ 7 จาก 120") และมีปุ่ม "ดูทั้งหมด" ห้ามซ่อนข้อมูลถาวร
- Empty state ทุกหน้าบอกสิ่งที่ต้องทำต่อ 1 บรรทัด + ปุ่มเดียว
- ห้ามสร้างตัวเลข/คำโฆษณา/badge social proof ที่ไม่มีอยู่จริง
- Acceptance: เจ้าของดู screenshot ก่อน/หลังและอนุมัติ ก่อนทำต่อ
